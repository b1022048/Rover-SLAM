# 變數傳遞分析（一）：系統介面層

> **閱讀範圍**：`Examples/Stereo-Inertial/stereo_inertial_euroc.cc` + `src/System.cc`
>
> 本版本只涵蓋「**應用層 ↔ System 介面層**」的變數傳遞：資料如何進入 System、在 System 內如何轉交、結果如何回傳與保護。
>
> ⚠️ **誠實邊界**：Tracking / LocalMapping / LoopClosing 三個執行緒之間透過 KeyFrame 佇列與共享 Atlas 的內部傳遞，**不在本版本範圍**（見「變數傳遞（二）」）。

---

## 0. 一張總圖

```text
main (stereo_inertial_euroc.cc)
  │  ① 建構參數 (voc路徑 / settings路徑 / sensor型態 / 是否開Viewer)
  │  ② vImuMeas 組裝 (vAcc/vGyro/vTimestampsImu → IMU::Point → vImuMeas)
  ▼
System 建構子 (System.cc:50)
  │  ④ 發配共享物件 (mpAtlas / mpKeyFrameDatabase / settings_) + 互設指標
  ▼            └──► [Tracking] [LocalMapping] [LoopClosing]  (內部 = 邊界，本版不講)
  │  ③ TrackStereo(imLeft, imRight, tframe, vImuMeas)
  ▼
System::TrackStereo (System.cc:283)
  │  ⑤ 轉交 Tracking：GrabImuData(逐筆) / GrabImageStereo(影像)
  │  ⑥ 寫回 System 成員：mTrackingState / mTrackedMapPoints (鎖 mMutexState)
  ▼  回傳 Tcw (Sophus::SE3f)
main 拿到 Tcw
```

## 1. main → System 建構子（啟動時一次性傳入「組態」）

| 項目 | 內容 |
| ---- | ---- |
| 呼叫點 | `System SLAM(argv[1], argv[2], IMU_STEREO, true)` （`stereo_inertial_euroc.cc:139`） |
| 進入點 | `System::System(const string &strVocFile, const string &strSettingsFile, const eSensor sensor, const bool bUseViewer, ...)` （`System.cc:50`） |
| 傳的是 | **組態**（詞袋路徑、設定檔路徑、感測器型態、是否開 Viewer），不是逐幀資料 |

**重點：參數 → 成員變數（變數生命週期）**
建構子參數是區域變數，函式結束就消失，所以 System 把需要長期保留的存進成員：
```cpp
mStrVocabularyFilePath = strVocFile;   // System.cc:118  （區域參數 → 成員，整個物件存活期可用）
// 初始化列表
mSensor(sensor)                        // System.cc:50   （感測器型態存成成員）
```

## 2.  main 內部：IMU 原始資料 → `vImuMeas`（最值得細講）

一條清楚的變數轉換鏈，全部在 main 內：

```text
LoadIMU (:276) ──► vAcc / vGyro / vTimestampsImu   (三個平行陣列, by reference 填值)
        │  主迴圈逐幀挑出「上一幀～當前幀」之間的 IMU (:177 while)
        ▼
IMU::Point(vAcc.x,y,z, vGyro.x,y,z, t)  (:179)     (原始三軸 → 打包成結構)
        │  push_back
        ▼
vImuMeas  (一幀對應一段 IMU)
        │
        ▼  傳給 TrackStereo
```

- `LoadIMU` 用 **傳參考**（`vector<...> &vAcc` 等）把讀到的值寫回呼叫端，是典型「輸出參數」寫法（`stereo_inertial_euroc.cc:39/276`）。
- `first_imu` 指標（`:118` 初始化、`:177` 推進）負責標記「下一筆還沒用掉的 IMU」，避免重複。
- 講法：**原始 IMU 三軸資料 → `IMU::Point` 結構 → 累積成 `vImuMeas` 一段 → 隨影像送入系統**。這是 Visual-Inertial 的關鍵同步機制。

## 3.  main → TrackStereo（每幀輸入 + 回傳位姿）

| 方向 | 變數 | 型別 / 傳法 |
| ---- | ---- | ----------- |
| 輸入 | imLeft, imRight | `const cv::Mat &`（傳參考，避免複製大影像） |
| 輸入 | tframe | `const double &`（時間戳） |
| 輸入 | vImuMeas | `const vector<IMU::Point>&`（這一幀對應的 IMU 段） |
| 回傳 | Tcw | `Sophus::SE3f`（World→Camera 位姿，回到 main） |

- 呼叫點：`SLAM.TrackStereo(imLeft, imRight, tframe, vImuMeas)`（`stereo_inertial_euroc.cc:192`）
- 進入點：`System::TrackStereo(...)`（`System.cc:283`）

## 4. System 建構子 → 把變數「發配」給三個模組（call site 可見）

System 是**分配中心**：它建立共享物件，再把**同一份指標**分給三個模組。

```cpp
mpTracker     = new Tracking(this, mpVocabulary_sp, mpFrameDrawer, mpMapDrawer,
                             mpAtlas, mpKeyFrameDatabase, ..., settings_, ...); // System.cc:222
mpLocalMapper = new LocalMapping(this, mpAtlas, ...);                          // :227
mpLoopCloser  = new LoopClosing(mpAtlas, mpKeyFrameDatabase, ...);             // :250
```

互設指標（讓三方互相找得到對方，`System.cc:255-262`）：
```cpp
mpTracker->SetLocalMapper(mpLocalMapper);
mpTracker->SetLoopClosing(mpLoopCloser);
mpLocalMapper->SetTracker(mpTracker);
mpLocalMapper->SetLoopCloser(mpLoopCloser);
mpLoopCloser->SetTracker(mpTracker);
mpLoopCloser->SetLocalMapper(mpLocalMapper);
```

| 共享變數 | 由 System 建立 | 發配給 |
| -------- | -------------- | ------ |
| `mpAtlas` | `System.cc:154` | Tracking / LocalMapping / LoopClosing |
| `mpKeyFrameDatabase` | `:149` | Tracking / LoopClosing |
| `settings_` | `:86` | Tracking / MapDrawer / Viewer |
| `mpVocabulary_sp` | `:131` | Tracking |

> ✅ 本版可講：「System 發配了什麼指標給誰」。
> ❌ 「模組拿到 mpAtlas 之後在內部怎麼用」屬於下一版（需讀模組內部）。

## 5. TrackStereo 內部 → 再轉交給 Tracking（這支函式已讀懂）

System 在 TrackStereo 裡把 main 給的資料**再往下交給 `mpTracker`**：

```cpp
// IMU：把 vImuMeas 拆成單筆，逐筆交給 Tracking
if (mSensor == System::IMU_STEREO)
    for(size_t i_imu = 0; i_imu < vImuMeas.size(); i_imu++)
        mpTracker->GrabImuData(vImuMeas[i_imu]);          // System.cc:350-352

// 影像：交給 Tracking，拿回位姿
Sophus::SE3f Tcw = mpTracker->GrabImageStereo(imLeftToFeed, imRightToFeed, timestamp, filename); // System.cc:354
```

講法：**System 是轉手層**——把 vImuMeas 拆筆交給 `GrabImuData`、把影像交給 `GrabImageStereo`、拿回 `Tcw`。
> ✅ 講「呼叫了什麼、傳了什麼、回傳什麼」。
> ❌ `GrabImuData` 內部如何把資料塞進佇列屬於下一版。

## 6.  結果寫回 System 成員（輸出變數，供外部查詢）

TrackStereo 結尾把 Tracking 的結果**快照**到 System 自己的成員：

```cpp
unique_lock<mutex> lock2(mMutexState);                  // 上鎖保護對外狀態
mTrackingState      = mpTracker->mState;                // 追蹤狀態
mTrackedMapPoints   = mpTracker->mCurrentFrame.mvpMapPoints;   // 當前幀地圖點
mTrackedKeyPointsUn = mpTracker->mCurrentFrame.mvKeysUn;       // 當前幀特徵點
return Tcw;                                             // 回傳給 main，return 後解鎖
```

意義：外部（Viewer / 查詢 API）只要讀 System 成員即可，不必直接碰 Tracking。

## 7. 變數保護：System 層的三把鎖

| Mutex | 保護的變數 | 出現位置 |
| ----- | ---------- | -------- |
| `mMutexMode` | `mbActivateLocalizationMode` / `mbDeactivateLocalizationMode` | `System.cc:312` |
| `mMutexReset` | `mbReset` / `mbResetActiveMap` | `System.cc:336` |
| `mMutexState` | `mTrackingState` / `mTrackedMapPoints` / `mTrackedKeyPointsUn` | TrackStereo 尾 |

這三把鎖示範了「跨 thread 共享的旗標 / 狀態變數如何被保護」。
